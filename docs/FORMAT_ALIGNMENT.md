```

2. Metadata (Location, Work Arrangement, Job Type, Experience)
3. Role Summary (opening paragraph, no heading)
4. Company Overview (optional)
5. About the Project (optional)
6. Key Responsibilities (bulleted)
7. Required Qualifications (bulleted, includes education)
8. Preferred Qualifications (bulleted, includes education)
9. Technical Skills (bulleted, optional)
10. Work Environment (bulleted)
11. Compensation and Benefits (optional)
12. Application Instructions (optional)
13. Closing Statement (engagement_details + closing_statement merged)
```

## How the System Maintains Alignment

### 1. System Prompt Governance (`jd_system.txt`)

The system prompt includes explicit formatting rules:

```
- Preserve explicit requirements and distinguish required vs. preferred
- Write role_summary as opening paragraph; starts with "<Company> is seeking a ..."
- Wrap job title and main focus in **double asterisks**
- Put engagement details in one sentence before closing statement
- Keep assumptions separate from publishable JD
- Use clear, inclusive language
```

### 2. Schema Validation (`jd.py`)

- `JobDescription` model enforces field types
- `engagement_details`: Single sentence covering employment type(s), hours, duration
- `education_requirements`: Marked with "preferred" text where applicable
- `work_environment`: Array of environment details

### 3. Formatter Rules (`jd-formatters.ts`)

Section ordering is deterministic:

```typescript
const candidates: Array<[string | null, string | string[] | null | undefined]> = [
  [null, jd.role_summary],           // No heading
  ['Company Overview', ...],          // Optional
  ['About the Project', ...],         // Optional
  ['Key Responsibilities', ...],      // Bulleted
  ['Required Qualifications', ...],   // Bulleted (education + required)
  ['Preferred Qualifications', ...],  // Bulleted (preferred education + preferred)
  // ... remaining sections
];
```

### 4. Quality Service Checks

Post-generation validation ensures:
- No core sections missing
- Metadata fields properly populated
- No template placeholders
- No domain term mismatches
- No repeated bullets

## Recommendations for Further Refinement

### 1. **Visual Template (Optional)**
If you want to surface the exact PDF layout in the UI, add a "Reference Format" button that shows a template breakdown.

### 2. **Engagement Details Validation**
The system prompt already says: *"Write engagement_details as one complete sentence..."*

Consider adding a frontend validation warning if engagement_details exceeds ~100 words.

### 3. **Company Name Banner**
Your reference PDFs show company name at the top. The system already supports this via the `companyName` export option:

```typescript
const exportOptions = { companyName: result?.company_name };
downloadPdf(result.job_description, exportOptions);
```

This is already implemented in [page.tsx:223](src/app/page.tsx#L223).

### 4. **Role Title Bold**
The system prompt requires: *"Wrap the job title and the single most important focus phrase in **double asterisks**"*

Ensure the LLM is consistently doing this. The Quality Service could add a check:

```python
# Check that role_summary contains at least one **bold** phrase
if jd.role_summary and '**' not in jd.role_summary:
    warnings.append(QualityWarning(
        severity="warning",
        section="role_summary",
        message="Role summary should emphasize the job title and main focus in bold."
    ))
```

### 5. **Metadata Formatting**
Both reference PDFs show clean metadata at the top. Your system already does this correctly via `getJobDescriptionMetadata()`.
